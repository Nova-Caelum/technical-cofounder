## Codex host contract

This installation runs Technical Cofounder in a **local Codex project**. Shared persona and workflow policies below still apply. These host mappings supersede Claude-specific mechanics in shared reference material:

- Before starting work, read `.codex/technical-cofounder/workspace-rules.md` in full. It contains the five shared workspace rules; they are a mandatory part of this installation. They live in a separate file so Codex does not truncate AGENTS.md at its document budget.
- Read `AGENTS.md` as the project entry point. Skills live in `.agents/skills`; invoke `$skill-name` or use the picker. Run `$tc-setup` for setup. There are no Claude plugin install or marketplace steps here.
- Four custom roles live in `.codex/agents/*.toml`: `technical-cofounder`, `engineer`, `devops-lead`, `lead-fde`. Use the host's available subagent tools and the role name, subject to the user's delegation policy. `Agent`/`ListAgents` mean the equivalent spawn/list/wait tools exposed by this Codex host; never invent tools or arguments. If custom roles cannot be selected, give the child the installed role's full developer instructions. Inherit the configured model; do not request Claude model aliases. If delegation is unavailable, report the missing independent audit; do not certify your own work as independently audited.
- A worktree is not implicit in a Codex child. Use the host's worktree tool or an explicit Git worktree when authorized, and include its absolute working directory in the brief. Shared checkouts must not be reset or cleaned. Verify the actual child's directory before edits.
- MCP services are `caelum-dev-team` and `hyperspace`, configured in `.codex/config.toml`. Use native MCP discovery or `codex mcp list`, never `claude mcp`. They start only through the shared environment provenance gate. Do not bypass a refused environment.
- `.codex/hooks.json` runs the shared safeguards through the host adapter. Project trust and exact hook-definition trust are separate user decisions; review with `/hooks`. Do not automatically approve them or silently disable guards. Hooks do not run in hosted cloud tasks.
- PostToolUse supplies the circuit breaker with recognizable shell exit codes and explicit MCP `isError` flags. Unknown results retain counters and emit a diagnostic; they are not proof of success. Native host errors without a PostToolUse event cannot be counted by this adapter. Transcript identity isolates threads when supplied; without it or agent_id, the host's session scope is the only available scope.
- Never run the Claude setup installer, alter `.claude` configuration, or install optional super connectors as part of this Codex setup. Optional services need their own documented Codex MCP configuration and user authorization. The core workflows have their existing manual fallbacks.
- Host references in examples and incident history are historical, not commands to execute. Codex session inspection uses the current host's transcript/read-thread tools when available; do not assume a Claude transcript directory.

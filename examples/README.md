# Worked example: toy-run

`toy-run/` is a complete run of the working loop on a toy goal, generated by the loop's own test (`tests/test_loop.py`). Nothing in it was written by hand after the run: every file is what a stage produced, and `loop.state.json` is what the gates recorded.

**The goal** (`toy-run/original_input.md`): add a `greeting.txt` holding "Hello, world" and a `greet.py` command that prints it.

## The stages, and what each left behind

| Stage | Skill | Wrote | Its gate checked |
|---|---|---|---|
| understand | `hs-understand` | `01_understand/Problem.md`, `tests.json` | the tests are valid verifier-lite criteria, at least one is executable, and one begins `WHOLE-PATH:` |
| decide | `hs-decide` | `02_decide/Decision.md`, `mapping.json`, `principles.json`, `Deferred.md` | both tests map to a component; "localized greetings" is cut, by name, under `## Deferred` |
| draft | `hs-draft` | `03_draft/PRD.md`, `workplan.json`, `criteria/*.json` | both tasks have a criteria file whose id matches, and every test is served by a task |
| build | `hs-build` | `greeting.txt`, `greet.py`, `tests/test_greet.py`, `verdicts/`, `RECONCILIATION.md` | both tasks are `done`, and each has a verifier-lite verdict with overall `pass` on its own criteria, from after the plan was filed |
| live | `hs-live` | nothing | there is no gate: a person runs the acceptance test and `confirm`s |

`loop.state.json` reads `status: live` and `current_node: build`. The build is over; the run is not done. Only a person moves it to `done`, so the example stops here on purpose.

Every gate in the run was first shown a broken artifact and refused it: tests with no `WHOLE-PATH:` criterion, a mapping that left a test unmapped, a workplan whose second task had no criteria file, and a reconciliation that declared the second task done before it was verified. A refusal records nothing, which is why none of them appear in the state file. The test asserts each one.

## Look at it yourself

From the repository root:

```
python3 plugins/base-novacaelum/bin/loop_state.py read examples/toy-run/loop.state.json
```

Re-verify a task with verifier-lite (this writes a new verdict into the example, so try it on a copy):

```
cp -R examples/toy-run /tmp/toy-run
python3 plugins/base-novacaelum/mcp/verifier.py /tmp/toy-run/03_draft/criteria/greet-command.json --root /tmp/toy-run
python3 plugins/base-novacaelum/bin/loop_state.py check /tmp/toy-run/loop.state.json
```

`check` re-hashes every file a gate froze. Edit one of them and run it again: `doubled_back_rounds` goes up by one, once per edit. That count is the run's evidence of fixing versus changing its mind.

## Two things that differ in a real project

- **The project and the run folder are one directory here,** so the example is self-contained: verifier-lite ran with `--root toy-run` and wrote its verdicts to `toy-run/verdicts/`. In a real project the run lives in `runs/<slug>/`, the verifier runs from the project root, and verdicts land in `<project>/verdicts/`.
- **The verdicts' `evidence` strings carry the temporary folder the example was generated in.** verifier-lite records the absolute path it checked; that path belonged to the generating machine and no longer exists.

## Regenerate it

```
python3 tests/test_loop.py --write-example
```

The run id and timestamps change; the shape does not. `python3 -m unittest tests/test_loop.py` checks that the committed example still passes its own build gate and that its frozen files still match their hashes.
